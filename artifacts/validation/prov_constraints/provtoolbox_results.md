### Root cause

The Python `prov` library v2.1.1 serializes multi-line attribute values using
Python-style triple-quoted strings in PROV-N (e.g. `"""line1\nline2"""`).  This is a
non-standard extension: W3C PROV-N specifies only double-quoted string literals with
standard escape sequences.  ProvToolbox 2.2.1's PROV-N parser does not support
triple-quoted strings and treats their content as free-form PROV-N tokens.  When it
encounters `generic_torch.sh:` (a filename with a colon, stored in a `ci_stdout_text`
attribute of activity `ex:qc_QC.Uni_78`), it attempts to parse it as a `prefix:localname`
QName and crashes because `generic_torch.sh` is not a declared namespace prefix.

The `extensibility: qnameDisabled false <token>` lines are debug messages produced for
every other unparseable token in the triple-quoted string bodies — they indicate the
same underlying parsing mode, but do not themselves represent PROV-CONSTRAINTS violations.
